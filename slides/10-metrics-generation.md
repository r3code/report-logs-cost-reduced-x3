# Побочный эффект: генерация метрик

- Раньше: **копипаст** VRL-кода для метрик каждого сервиса
- Теперь: единый `metrics-catalog.yml` → **Ansible/Jinja**
- Время на добавление метрики: **5 часов → 20 минут**
- Единый источник истины, ноль рассинхрона

::right::

<div class="pl-4">

```yaml {all|1-2|3-4|5-8|all}
# metrics-catalog.yml — генерация
# VRL-правил и SQL-схем через Jinja
services:
  - name: billing
    metrics:
      - http_request_duration_seconds
      - payment_errors_total
    ttl_hours: 720
```

<div class="mt-4 text-sm opacity-70">

Jinja-шаблон → VRL transform + ClickHouse DDL
Один каталог — все конфиги синхронны

</div>

</div>

<!-- Примечание спикера: Приятный побочный эффект архитектуры. Раньше добавление метрик для нового сервиса — это копипаст VRL-кода, ручная правка трансформов, синхронизация SQL-схемы. Пять часов работы и высокий риск ошибиться. Теперь у нас единый каталог — metrics-catalog.yml. Из него Ansible с Jinja-шаблонами генерирует и VRL-правила для Vector, и DDL для ClickHouse. Время — 20 минут на новый сервис. Один источник истины, ноль рассинхрона между конфигами. Это и есть инженерная культура: автоматизируй рутину, освобождай время для задач посложнее. -->
